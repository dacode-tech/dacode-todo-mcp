# Agent Knowledge Base

Cross-cutting procedural knowledge shared across all domain skills. Area
documentation lives at the repo root and under `crates/` and `docs/`
(indexed in [`INDEX.md`](INDEX.md), generated by `tools/agents-index.py`).
The plan and the domain model live in `docs/todo-mcp-design.md`.

> **Read [`.agents/skill-base.md`](../skill-base.md) first** — it defines
> the mandatory Pre-Task Knowledge Search and Canonical Command protocols
> that every skill (orchestrator + workers) inherits. The articles here
> are the *content* those protocols point you to.

The knowledge base starts nearly empty and grows as work happens — see
[`../pitfalls-live.md`](../pitfalls-live.md) for the adaptive record.

## Structure

```
knowledge/
├── INDEX.md                        # generated index of every AGENTS.md (tools/agents-index.py)
├── patterns/                       # Code shapes and how-tos (empty until code exists)
│   └── .gitkeep
└── workflows/                      # Build, verification and operational procedures
    ├── build-and-test.md           # cargo gates, golden files, MCP smoke tests, output discipline
    └── task-tracking.md            # the three trackers, node kinds, verify methods, the exit gate
```

## Knowledge Evolution Protocol

Agents update this knowledge base as part of the post-commit workflow.

### What goes where

| Knowledge type | Location | Example |
|---|---|---|
| Scope, plan, domain model, storage options | `docs/todo-mcp-design.md` | The graph semantics, the tool surface, what determinism requires — moves only by user decision |
| **A fact established the hard way** | `docs/todo-mcp-design.md`, its numbered section | A measured load time that decides D1; an rmcp API constraint that shapes §6. This is the expensive part and must survive the session |
| Area implementation notes | `crates/<crate>/AGENTS.md`, `docs/<area>/AGENTS.md` | What the store crate actually does, and where it diverges from §4 |
| Reusable code shapes | `.agents/knowledge/patterns/` | How a new MCP tool is added end to end |
| Build/verification procedures | `.agents/knowledge/workflows/` | How to regenerate a golden file and review its diff |
| Traps, gotchas, workarounds | `.agents/pitfalls-live.md` | A clippy lint that fires only on macOS; a client quirk in the handshake |
| What I am doing now, and how I will know it worked | `tools/tasks.py` → `.agents/cache/tasks/<branch>.yaml` | Gitignored, branch-keyed. Convention in `workflows/task-tracking.md` |
| What the project has done, and what blocks it | `docs/implementation/TODO.md` | Committed. The only tracker a reviewer can see |
| Recurring confirmed lessons | `.agents/pitfalls.md` | Promoted from `pitfalls-live.md` at milestone gates |

### Article format

```markdown
# <Title>

## When to Use
Brief description of when this pattern/workflow applies.

## Pattern / Procedure
The actual content — commands and code, not prose about them.

## Pitfalls
Known gotchas specific to this pattern.

## References
Paths, spec sections, related articles.
```

### Adding new articles

1. Create the file in the right subdirectory (`patterns/` or `workflows/`).
2. Follow the article format above.
3. Link it from this README's structure block.
4. If it supersedes or constrains a spec section, cite the section — and
   if it *contradicts* one, stop and raise it with the user instead.
5. Run `tools/check-links.py`.
6. Commit with the `knowledge:` prefix (review-exempt, no trailer).

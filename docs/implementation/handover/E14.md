# E14 — the shared-server arc: the handover

The arc: D25 signed 2026-10-13 — one binary, two modes. The
no-argument invocation (the one every existing client config uses)
becomes the thin stdio shim: it connects to the root's daemon over
`<root>/serve.sock`, spawning it when absent, and proxies MCP —
retrying the connection for a bounded window before answering the
tool execution as a structured `io` error, no fallback. The
extra-argument invocation is the daemon: one process per root,
serving every connected session concurrently (each connection its
own MCP session — handshake, request ids, D8 default repo), holding
the store handles, owning the live-view listener (the watchdog
retires). Updates: kill the daemon gracefully (stop accepting,
drain in-flight within the timeout, exit); the freshly installed
binary starts under the shims' retry window — no session restarts,
ever. The store stays local files (§4); the CLI subcommands are
daemon-less. Four units: U64 (the rmcp socket survey — the
feasibility gate), U65 (the daemon), U66 (the shim), U67 (the
update cycle end-to-end and the docs).
